# Development Visual Editor

Run `npm run dev:editor`, then open `http://127.0.0.1:5175/__editor`. The editor also works at `/__editor` on any freshly started localhost Vite development server. Restart an older development server after adding the editor plugin. The editor UI and save endpoint are not included in production builds.

## Editing

- **Scene** renders the real `App`, with an in-memory child and settings. Its layout, instrument settling, scene components, responsive CSS, and avatar renderer are the game's own implementations. Choose any of the seven scenes and regular objects or either visitor.
- **Objects** shows all 28 scenery objects and all eight instruments, using their actual SVGs and reaction CSS. **Character** opens the real caregiver dialog directly on its avatar step. **Menu** uses the real child-selection screen with a preview profile.
- Use **Select** to inspect an item, **Drag** to move scene objects, the child, instruments, or decorative SVG groups, and **Interact** to try the normal controls. The layers icon selects individual SVG shapes. The searchable outline and **Browse SVG parts** also reach covered shapes, gradient stops, and reaction/effect layers.
- Edit SVG path text (`d`), points, shape coordinates, transforms, fills, strokes, opacity, and gradient colors in the side panel. **Edit SVG points** exposes on-canvas anchors and Bezier control points, polygon vertices, and primitive size/radius handles. Drag a handle or focus it and use arrow keys (Shift for a larger step). Colors have swatches as well as text fields.
- Select an item to expose eight resize grips; **Aspect lock** preserves proportions. **Drag** repositions it. Named outline entries include the barn, hills, pond, and individual trees; the outline reaches items covered by other artwork. Direct scenery drags record SVG-coordinate translations, and ordinary object drags retain their percentage baseline/center.
- **Fit responsive endpoints** measures the item's existing geometry at the fixed **360 x 240 minimum** and **1920 x 1080 maximum**. Switch to either endpoint, then drag/resize on the canvas or adjust its numeric center and dimensions. The other endpoint is preserved. Width/X interpolate against viewport width; height/Y interpolate against viewport height. Generated bounded size formulas are visible in the inspector. Fitted items can only be transformed at endpoints; intermediate/device views preview interpolation. Below/above the endpoints geometry clamps, but the game's viewport itself is not cropped or letterboxed.
- Existing scene object sizes and instrument drawings use these same endpoint bounds. Fitting does not autosave or change other objects. Positions are percentage centers; sizes are pixels at each endpoint. Landscape fitting accounts for the real renderer's SVG transforms and aspect stretch. Shape geometry and color apply to the matching asset across views; landscape artwork is scene-specific and object placement is scoped by sound.
- Instrument placement establishes a **home position**, not a permanent CSS lock: in the normal game instruments still drag, equip, settle, and put down normally. Instrument drawings resize with their hit areas. Layout changes do not edit family profiles.
- In **Character**, choose a hairdo/top/bottom, then select its named part or individual path. Hair-front/back edits are scoped to that hairdo; top and bottom edits are scoped independently to that clothing item, regardless of other outfit choices. These edits appear in character choices and gameplay.
- **Layer Order** supports a numeric depth and backward/forward/front/back commands. Background SVG shapes/groups are painted at their own scene depth without moving React-owned nodes. A depth-60 barn can cover a depth-45 cow; changing the cow's depth can bring it in front again. Controls remain separate from world artwork.
- **Compact viewport only** limits a selected item's override to a maximum viewport width. Each selector currently has one rule: enabling this changes that rule's scope rather than creating a second desktop/compact variation. Built-in responsive rules remain underneath it. Reset a property to return to the renderer's original value.
- Pause/resume and replay animations from the toolbar. The object lineup also has an instrument animation toggle. Choose the reaction or animated SVG group to edit its duration, delay, timing curve, iteration count, or transform origin. Optional sound initializes the real sound engine; default previews are silent.
- Enter viewport dimensions within the fixed limits, use an endpoint/device preset, or drag the lower-right resize handle. Fit zoom scales the iframe visually; the inner game still receives the exact displayed viewport dimensions. Portrait retains the game's orientation guard.

## Saving And Isolation

Edits live only in the editor's memory until **Save to project** writes `src/data/visual-overrides.json`. The game loads this committed-format file in development and production. The initial empty file leaves the artwork unchanged. Saving uses a fixed file path, localhost/same-origin checks, visual-property validation, an atomic file replacement, and a content revision check. A stale editor cannot overwrite an external edit: export its draft and reload instead.

Undo/redo, per-property reset, selected-item reset, discard, JSON export/import, and an unsaved-navigation warning are provided. Drafts are not automatically persisted. Export a draft before restarting or leaving the editor if it is not ready to save. Vite may reload after a save. Preview profiles/settings never use the game's local storage.

## Limits

This is a visual property editor, not an arbitrary JavaScript editor. Path anchors and Bezier controls are editable, but arc radii/flags and adding/removing path commands still use SVG text. It does not create/delete scene entities, rewrite React structure, edit audio synthesis or recordings, or change the collision/settling algorithm, celestial motion calculations, animation keyframe bodies, and other JavaScript constraints. Those still require source changes. CSS placement/size formulas, SVG transforms, and animation timing are editable.

Overrides address SVG elements by their renderer hierarchy, with semantic anchors for avatar parts. Major source changes that reorder shapes can invalidate a saved selector; review/reset affected overrides when refactoring artwork. The new avatar part wrappers replace old whole-outfit descendant paths; any legacy avatar path rules should be reselected using the named parts. Child appearance choices and age remain preview inputs, not changes to the game's default avatar or a saved family profile. The lineup uses larger fixed display sizes for inspection; use Scene/Character/Menu for exact layout checks. Responsive fitting is available in Scene. Sound playback and physical-device behavior still need manual verification.

## Validation

Run `npm run test:editor`. Node tests cover SVG parsing, handle edits, endpoint interpolation/clamping, home positions, and real filesystem persistence in temporary directories. Browser tests use a mocked save endpoint so validation never modifies your project's artwork. Checks include live SVG edits/undo, isolated drafts, saved-file loading, real character dialog, independent outfit-item editing, point controls, animation/visitors, endpoint canvas resizing, actual SVG geometry, cross-SVG layering, and normal-game dragging/equipping after saved placement. Native mouse gestures are desktop-only; other checks run on desktop and compact touch Chromium. These are focused development checks, not the full release gate.
